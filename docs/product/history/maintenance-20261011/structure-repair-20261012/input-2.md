# TraceLens 修复方案：正式结构、候选关系与分层需求的准确展示

基线：`tracelens@8680013c5dbb3ac75b68768a0aac4f5551bff938`（master / origin/master）。

目标：使用户直接理解“哪些结构已明确、哪些尚为推断、某些需求为什么没连入当前图”，并能沿真实层级查看需求、功能和 Task；不替 vNext 创造结构或作业务决定。

## 1. 固定基线中的事实与本轮边界

product-view.ts 的 productView 已按 resolved、declared、active 选择正式关系；goalRequirements 沿这些关系计算所选目标下的需求。[L1] 这与 vNext 契约一致，本轮不放宽。

product-graph.tsx 已能在局部关联视图用虚线展示 inferred，保留关系理由及来源。[L3] 不需要新建候选关系子系统。

product-hierarchy.ts 已有当前 requirement 组成 DAG 的展开与自身/后代绑定汇集。[L4] 本轮复用这套能力，而不是新建一套无依据的层级树。

RequirementsV3 主图目前按目标的正式可达需求取节点；主要入口没有充分解释推断关系未进入图的原因。该组件还将非 goal 节点统一标为“需求”，并对它们统一求评估；目标节点的主图选择与目标详情也需保持一致。[L2]

因此，本轮核心是消费和交互修复，不默认修解析器，也不把 TermLink 的 product_classification 解释成通用结构协议。

## 2. 最终交付的界面内容

### 2.1 主图仍展示正式当前结构

默认保留当前目标、正式支撑/组成关系和适用节点。只认核心条目与关系，不从标题、正文序号、扩展分类、Task 或文件目录自动生成边。

有结构但没有可用 assessment 时，仍可浏览结构。结果显示尚未判定和具体原因；不要求先获得结论才能出现在图里。

### 2.2 增加一条轻量结构说明

在主图附近显示当前快照和所选目标相关的简短说明，示例：

> 当前有若干需求未通过已声明关系连入所选目标；另有候选结构关系可查看。

实际数量由真实快照计算，不硬编码 TermLink 的 26 条；明确数量是在全项目还是当前目标上下文内。关系条数、需求个数和 Task 个数分别统计，不称覆盖率或完整度。读取范围不完整时，计数必须注明只针对本次已读取内容，不能冒称全项目总数。

无异常时不常驻显示长说明，不新增大面积原则卡片。

### 2.3 两个可直接进入的查看入口

**查看候选关系。** 在当前页面打开候选清单及局部关系详情，复用现有虚线图、理由和来源组件。默认只列与当前目标/选定节点实际有关的已记录候选，可明确切换到全部候选。候选展示不改变正式主图成员及正式汇集结果。

**查看未连入需求。** 展示当前快照可读、但不在所选目标正式路径中的要求，允许搜索并进入原详情。明确区分“属于另一个目标”“已有候选路径”“核心关系未记录或尚未确定”“引用/方向/身份异常”，不能将所有情况统称为文档坏了。

本轮不要求把全项目候选同时叠在主图上。已有局部虚线图加清晰入口即可完成候选可见性；不另做全局候选布局/推理系统。

### 2.4 已确定与未确定互不冒充

候选的类型、端点和来源按既有解析结果展示。无效或身份含糊的边只在问题/来源区域说明，不为了可视化补造端点或修成有效正式关系。dismissed 留在历史/明确打开的区域，不复活为当前候选。

“没有声明路径”只是结构事实，不等于该需求不属于产品，也不等于功能没有实现。真实未决保留，其他已声明部分照常可见。

## 3. 分层需求阅读

### 3.1 使用现有组成 DAG

将现有 requirementHierarchy 能力接入实际需求主图需要的展开、搜索及缺口筛选路径；原路径已具备则复用，不改成平行算法。默认先看高层 requirement，再逐层展开子要求；不把新增功能点一律平铺到首页。

共享节点按稳定身份呈现，任一有效展开路径可达；折叠一个父项不能隐藏另一个仍展开路径下的共享节点。没有可展示父项的子项保留入口。

搜索和缺口筛选保留必要祖先；未展开不等于缺失。筛选不改写项目顺序，布局深度也不产生实施顺序。

### 3.2 节点类型与结论分开

| 节点 | 标签与结论处理 |
| --- | --- |
| goal | 显示“目标”；其目标级结论用该 goal 自身的当前范围及所选对象，与详情一致，不错误套所选父目标的 goal_id。 |
| requirement | 显示“需求/具体要求”；按实际选定目标、scope、subject 使用现有 selector；不根据无子项自动认定是功能类型。 |
| module | 显示“模块/分类”；不调用 requirement/goal 的达成选择来制造“冲突/尚未满足”，不显示为需求。 |
| 推断/问题节点 | 仅在候选或问题上下文说明来源与确定程度，不升级为可汇总的正式交付对象。 |

不新增 module 评估、Feature 状态或功能完成率。对 goal 的修正只是保持节点与已有详情语义一致，不新建目标达成算法。

### 3.3 功能点表达的边界

v3 独立子 requirement 可以成为节点、拥有自己的关联及范围报告。正文中的局部编号清单继续在完整需求正文中读取；不能把数字编号自动变成稳定 ID、自动绑定 Task 或自动继承父项结论。

界面可明确区分“可展开的已登记子要求”与“正文细节”。只有保留完整正文仍不等于实现了逐功能节点管理；也不能反向要求所有正文句子都结构化。

## 4. Task、来源与选择状态

沿用 requirementBindings 对有效当前组成后代的关联汇集，按真实 Task 身份去重并保留具体角色、覆盖和来源。不能沿候选边、一般 supports、depends_on 或历史边新增父层汇集；已有具体关联自身的 origin 仍如实显示，结构来源与 Task 生命周期不得混淆。

可信 Task 身份有可读 Runtime 状态时，另一条关联的来源问题不抹去这个状态；closed 仍是已关闭，paused 仍是已暂停。只关联父项的 Task 不自动散发给每个功能点。

保留目标、对象、scope、需求、搜索/过滤、展开、候选面板和滚动的必要状态。从 Task/Step 或来源返回原上下文；项目切换遵守已有隔离机制，不将相同 ID 跨工作副本复用。

Task 数据仍走已有 Runtime 只读查询和快照降级。不能因产品结构缺口新增 adopt、close、rebuild、文档写回或自动维护动作；也不扩大全项目查询和日志重放。

## 5. 建议的实现位置

| 文件/范围 | 最小改动 |
| --- | --- |
| src/shared/product-view.ts | 保留正式 productView/goalRequirements/selector 语义；增加可复用的当前结构说明派生，或放在紧邻的展示辅助模块。 |
| src/shared/product-hierarchy.ts | 复用现有组成 DAG 和绑定汇集；只修有场景证据的展开/去重问题，不加入候选语义。 |
| src/web/product-v3.tsx | 加主图说明、候选/未连入入口、实际分层展开、准确类型及目标节点评估上下文。 |
| src/web/product-graph.tsx、product.tsx | 复用候选理由/来源、完整关系和详情；补同页入口与返回状态，不重写所有关系展示。 |
| 相关样式及既有 tests | 小范围样式与行为回归，不顺带重做概览主题或全部页面。 |
| product-reader.ts / product-index.ts / product assets | 默认不变。仅当共同样例证明有效 v3 关系被漏解析时，定位独立最小修复并补回归。 |

展示派生可以计算已知关系的可达性和数量，但不能解释自然语言 classification/coverage 推理业务。读取预算、异常边和工作副本边界沿既有机制，不建立第二套权威结构或新核心字段。

## 6. 现状、整理后及增量三组验收输入

**整理前。** 使用固定 TermLink 资料的只读副本，重现主图正式关系不足；页面明确为何未连接，候选理由及需求正文仍可到达。该场景不修改真实资料。

**整理后。** 使用第三份方案实际保存的采用结构，核对核心关系已被消费、所选独立细项可展开、共享节点与候选分离；具体节点和边以真实交接清单为依据，不硬编码“全部连通”。

**新增演练。** 在隔离工作副本中新增有明确父项的合成要求，经新 vNext Skill 同次保存；刷新后正确显示，不临时增加 classification 专属解析。不把演练内容提交成 TermLink 的真实新增业务。

## 7. 验收场景

| 场景 | 通过要求 |
| --- | --- |
| 根目标有效，只有候选结构边 | 显示正式图的真实范围并解释未连接原因；候选和未连入入口可用。 |
| 一条已声明合法路径 | 能到达所选目标下需求；不依赖结果报告才显示。 |
| 其他目标、planned/retired、搜索筛选 | 区分不在本目标/不在当前范围与真正缺结构；可按明确入口查原文。 |
| 推断/声明共存 | 虚线候选不参与正式归属、Task 汇集或满足结论计算。 |
| 多层 requirement 与共享子项 | 展开、折叠、搜索及缺口祖先保留正确，稳定 ID 不复制。 |
| module 与子 goal 出现在图中 | 类型正确；module 不被评估为需求；goal 节点与自身详情的选择一致。 |
| 功能仍只是正文 | 原文可看但不伪造独立节点及其状态。 |
| 关联有冲突而可信 Task 仍可定位 | 真实生命周期和导航保留，来源问题另示。 |
| 页面导航 | 需求→Task/Step→返回、来源→返回、候选→正式图均保留上下文。 |
| 查询失败、结构部分可读 | 继续显示可用内容，不报告零需求/零任务或全部完成，不写被观察项目。 |

确定性模型回归与实际页面交互分别保留。页面至少核对上述三个输入的主图、候选入口、独立细项、类型和下钻返回。可复用现有有限浏览器用例，不新增一套庞大端到端框架。

基线 package.json 已有以下入口，可按实际影响执行，均为计划而非本次结果：[L5]

```bash
npm run typecheck
npm test
npm run build
npm run test:browser:product
npm run test:browser:scoped
npm run test:browser:full-scope
```

具体浏览器运行前读原测试说明和隔离环境要求；无需为了单一入口变化承诺所有平台验证。正式交付说明实际环境、输入、失败与未验证范围。

## 8. 完成标准与明确非目标

完成标准：数据缺正式结构时能解释，数据有正式结构时能准确消费，未连入需求不会无声消失，候选可查但不被采纳，独立功能点能分层查看，生命周期和结果不混淆。对照同一基线和整理后资料验收，不只展示手绘效果或完美夹具。

不自动把 product_classification 转为 module 或父需求；不批量接受推断；不新增“采纳关系”写回按钮；不重做 Runtime 查询、Task reducer、报告选择算法或全局布局；不借本轮修改此前另有采用决定的概览风格和排序偏好。
